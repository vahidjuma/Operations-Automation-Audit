AI-Driven Digital Operations Assistant

A pilot system that runs a tractor ploughing and vehicle operations business: bookings, jobs, fuel, maintenance and cash, connected end to end. This repository is submitted for an audit before real-world testing.

How it works View the repository

How it works

Data moves in a loop between the website, the automations and the spreadsheet.

  1. 1. Softr websiteCustomers and staff enter bookings, acreage and job details through forms and buttons. Softr sends the data out through webhooks.
  2. 2. Make.com automationsCatch the webhooks, route each record to the right sheet tab and hand text to the AI where needed.
  3. 3. OpenAIStructures raw inputs, writes the weekly analysis and drafts email replies.
  4. 4. Google SheetsThe single source of truth for jobs, customers, tractors, trips, maintenance and transactions.
  5. 5. Sync back to SoftrMake pushes updates back so users see current data on the website.

The automations

Seven Make.com scenarios, exported as JSON in the repository.

Webhook from Softr to Google Sheets

Receives Softr data and adds rows to Trip logs, Customers, Login, Maintenance and Transactions. A second route sends text to OpenAI.

Web mapping back end to Softr

Uses OpenAI, adds a Maintenance row and creates a Softr user, closing the loop back to the website.

Weekly report v2

Reads one weekly digest cell from the sheet, has GPT-4o-mini write a plain-text report, and emails it to the managers.

Weekly analysis prompt

Lists the sheet tabs, filters their rows and emails the analysis.

Digital Operations Assistant AI agent

An agent that routes tasks, supervises scenario results and flags errors to the manager.

Email response prompt

Watches for new emails and drafts a reply with OpenAI.

Integration HTTP

Sends SMS through the Africa's Talking messaging API (sandbox).

Open issues for the audit

These are the problems the audit is meant to solve.

  1. Credit drain. The two-way sync between Softr and Sheets uses up Make operations quickly.
  2. Multi-sheet mapping. One webhook must route data to different tabs without hardcoded values.
  3. AI output format. Unexpected markdown from OpenAI can break scenarios before data reaches the sheet.
  4. Access boundaries. The AI module needs tighter limits on which sheets and rows it can read and write.
  5. No live business data yet. The AI works on system structure, not real constraints or supplier details.
  6. Slow webhook testing. Testing relies on live clicks in Softr, which also costs operations.
  7. Weak error handling. Failed API calls can drop data without alerting the manager.
